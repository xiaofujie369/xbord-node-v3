## 二、修复的问题（均先在原代码上用测试复现，再修复）

1. **SSRF 绕过**：私网拦截只匹配 IP 字面量，`localhost`、泛解析域名可直达本机服务；`0.0.0.0` 未拦截（Linux 上等同本机）。sing-box 先 `resolve` 再匹配并增加 `ip_is_private`；xray 改用 `IPOnDemand`；两内核共用一份拦截网段。
2. **设备数限制绕过**：超限时按字典序更小的新 IP 会被放行；检查与登记非原子，64 路并发在上限 3 时放进 13 个设备；xray 不统计 UDP，纯 UDP 客户端不占名额。
3. **删除用户后连接仍在**：sing-box `CloseByUUID` 为空实现；xray 删除用户只阻止新握手。现按 UUID 追踪 TCP/UDP 连接，删除或更换 UUID 时立即断开，并拒绝删除前已认证、删除后才到达的握手。xray 更换 UUID 时旧凭据未移除，已修复。
4. **UDP 流量统计错误**：零拷贝路径上下行记反；此外 sing 的计数器解包逻辑会跳过可替换的包装层，UDP 下行从未计费、也未限速（部署测试中发现）。限速写入短写导致连接中断，一并修复。
5. **xbctl upgrade 不安全**：下载后不校验即以 root 执行；版本参数可注入路径；重启后不检查健康状态；成功后删除备份；默认从上游仓库下载会覆盖本 fork。现要求 SHA256SUMS（或手动指定哈希），校验前不赋执行权限，加锁，重启后持续检测服务存活，失败自动回滚并保留备份；CI 发布 SHA256SUMS。
6. **热重载与回滚失败**：入站重建失败时旧监听已被移除且无回滚；重启时新实例在旧实例仍占端口时启动，必然 `address already in use`；xray 因 SO_REUSEPORT 在排空期内（最长 5 分钟）把新连接分给旧配置实例；服务层把被拒绝的配置当作当前配置，并在每次轮询重复应用。均已修复。
7. **sing-box fork 兼容问题**：fork 中 mieru、hysteria v1 没有用户热更新接口，原代码将其视为更新成功，用户变更静默失效。现改为重建入站。

## 四、遗留问题

1. sing-box fork 的 `UpdateUsers` 替换认证器时无同步，与并发握手存在数据竞争（原有问题，需在 fork 中改用 `atomic.Pointer`）。相关测试在 `-race` 下跳过该步骤。
2. xray 的 `IPOnDemand` 在路由判断与出站拨号时分别解析，理论上存在 DNS 重绑定窗口；sing-box 复用解析结果，无此问题。
3. xray 内核未做真实客户端实测（实测与部署测试均使用 sing-box 内核），仅有单元与运行时测试。
4. 本 fork 现有 Release 未提供 SHA256SUMS，新版 xbctl 会拒绝从中升级，需要先按新 CI 发布一次带校验文件的 Release。
5. 被删除测试用户在面板统计表中可能留有当日流量统计记录（不影响计费与真实用户）。

## 五、部署与回滚

部署（建议先在一台节点灰度）：
1. 用新 CI 构建并发布带 `SHA256SUMS` 的 Release。
2. 备份当前二进制与配置，替换二进制，重启服务，确认日志出现 `started, N users`，并用客户端实际连通测试。
3. 观察 1 小时：面板流量上报、在线 IP、设备数是否正常。UDP 下行开始计费后，用户用量会比旧版略高，属修复后的正确结果。

回滚：恢复备份的旧二进制并重启服务即可；配置格式与面板接口均未改变，无需迁移。使用新版 `xbctl upgrade` 时，旧版本会自动保留为 `*.bak`，失败时会自动回滚。
